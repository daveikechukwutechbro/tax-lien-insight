# Deploying Tax Lien Insight to Cloudflare + Neon (free tier)

Target architecture (all free-tier, commercially usable):

```
Cloudflare Pages/Workers  →  frontend (TanStack Start, Nitro output)
Cloudflare Workers        →  backend  (Hono, src/worker.ts)
Neon PostgreSQL           →  authoritative data (pooled connection)
Resend / RPC / R2         →  email / USDC verification / file storage
```

The backend Worker is verified to bundle via `wrangler deploy --dry-run`
(696 KB / 150 KB gzip). On Workers, `db/pool.ts` automatically uses
`@neondatabase/serverless`; `pg` is aliased out (`wrangler.jsonc`). All
SERIALIZABLE transactions and row locks work identically.

---

## 1. Neon setup

1. Create a project at neon.tech.
2. Branches: keep `main` as **production**; create `development` and
   `staging` branches from the Neon console. Never run experiments on main.
3. Copy TWO connection strings:
   - **Pooled** (hostname contains `-pooler`) → runtime `DATABASE_URL`.
   - **Direct** → migrations only (`DATABASE_DIRECT_URL`).

## 2. One-time schema setup (run from your machine)

```bash
cd backend
# point DATABASE_DIRECT_URL (or DATABASE_URL) at the DIRECT string first:
npm run migrate
npm run seed            # development branch only — never production

# create the first super_admin (one-time):
ADMIN_BOOTSTRAP_SECRET=<random> ADMIN_EMAIL=you@example.com \
ADMIN_PASSWORD=<strong> npm run admin:bootstrap
```

## 3. Backend Worker deploy

```bash
cd backend
npx wrangler login
npx wrangler secret put DATABASE_URL          # pooled connection string
npx wrangler secret put AUTH_SECRET           # long random string
npx wrangler secret put ADMIN_BOOTSTRAP_SECRET
npx wrangler secret put RESEND_API_KEY
npx wrangler secret put EMAIL_FROM
npx wrangler secret put APP_URL               # frontend public URL
npx wrangler secret put USDC_NETWORK
npx wrangler secret put USDC_TOKEN_CONTRACT
npx wrangler secret put USDC_CONFIRMATION_THRESHOLD
npx wrangler secret put BLOCKCHAIN_RPC_URL    # when ready for USDC verification
npx wrangler secret put CRON_SECRET
npx wrangler deploy --config wrangler.jsonc
```

> `--config` matters: the repo root contains a `.wrangler/deploy/config.json`
> generated by the frontend build, which confuses config auto-discovery.

Smoke test:

```bash
curl https://tax-lien-insight-backend.<your-subdomain>.workers.dev/api/v1/health
# expect: {"success":true,"data":{"status":"ok","database":"ok",...}}
```

## 4. Frontend deploy

The repo's build already emits Cloudflare artifacts (Nitro generates
`.output/server/wrangler.json`):

```bash
# at repo root
npm install
BACKEND_API_URL=https://tax-lien-insight-backend.<subdomain>.workers.dev npm run build
npx wrangler deploy --config .output/server/wrangler.json --name tax-lien-insight-app
```

Or use the Cloudflare dashboard → Workers & Pages → connect the GitHub repo,
build command `npm run build`, and set env var `BACKEND_API_URL` in project
settings before deploying.

## 5. Environment separation

| Env | Database | Backend | Notes |
|---|---|---|---|
| development | Neon `development` branch | local `npm run dev` | seeds allowed |
| staging | Neon `staging` branch | optional second Worker | |
| production | Neon `main` | Worker above | never seed fake data |

## 6. Scheduled jobs (later)

Vercel-style cron becomes a Workers Cron Trigger in `wrangler.jsonc`:

```jsonc
"triggers": { "crons": ["*/15 * * * *"] }
```

pointing at an authenticated `/api/v1/jobs/tick`-style route protected by
`CRON_SECRET`. Job handlers are already idempotent.
